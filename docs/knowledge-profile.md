# Knowledge profile: how BrainForge uses OKF v0.2

`knowledge/` is a conformant [OKF v0.2](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/main/SPEC.md) bundle. BrainForge adds a few conventions on top. All of them use OKF's extension points (extra keys, body sections), so any OKF consumer can still read the bundle.

## Layout and identity

- One concept per file: `knowledge/<group>/<slug>.md`, with one level of grouping and kebab-case slugs.
- The concept ID is the path without `.md`. Concepts are never renamed or deleted. An obsolete concept gets `status: deprecated` and links to its replacement.
- Default groups:

  | Group | Types |
  |---|---|
  | `sources/` | `Source Document` |
  | `entities/` | `Person`, `Organization`, `System`, … |
  | `topics/` | `Topic` |
  | `decisions/` | `Decision` |
  | `milestones/` | `Milestone` |
  | `risks/` | `Risk` |
  | `actions/` | `Action Item` |

  Brain instructions can add groups and types.
- `index.md` (with `okf_version: "0.2"` at the root) and `log.md` are generated by BrainForge after every change. Rebuild the indexes with `brainforge knowledge index`.

## Provenance

Every ingested document becomes a **source concept**, `knowledge/sources/<slug>-<sha12>.md`. It doubles as the ingestion record, and its `brainforge:` block holds the run metadata:

```yaml
type: Source Document
title: Project meeting 2026-10-28
resource: ../../archive/3f2a9c41b7d0/meeting.pdf   # the archived original
generated: { by: brainforge/claude-opus-5-5, at: 2026-10-28T10:12:00Z }
brainforge:
  sha256: 3f2a9c41b7d0…        # idempotency key
  original_name: meeting.pdf
  entry: cli                   # cli | inbox
  agent: claude/claude-opus-5-5
  base_commit: 9c1e…
  instructions: [framework:policy.md@0.1.0, instructions.md@a41b…, sidecar:meeting.pdf.sidecar.md@77d0…]
```

Knowledge concepts:
- list the source in `sources` (`resource: ../sources/<file>.md`);
- attribute each claim with a footnote whose label is the source id (`[^meeting-…]`);
- put page and slide locations in the claim text, e.g. "(p. 3)".

BrainForge enforces this on every ingestion:
- each changed concept cites the new source;
- existing `sources` entries are never removed;
- every footnote label has a matching `sources` id.

## Changes, history and conflicts

```markdown
# Current state
Integration testing starts on 2026-11-17.[^meeting]

# History
- 2026-10-01: planned for 2026-11-10, superseded by the 2026-10-28 meeting.[^plan][^meeting]

# Conflicts
- Plan v3: go-live 2027-01-15.[^plan] Meeting: move to February proposed, not decided.[^meeting]
```

- When a source *explicitly* supersedes an earlier statement, the earlier one moves to `# History`.
- Otherwise, both statements are kept under `# Conflicts`. A newer statement is not automatically more authoritative.

## Trust

- `generated` is stamped by BrainForge: `by: brainforge/<model>` and `at`.
- `approval` (BrainForge profile) is `pending`, `approved` or `discarded`; a concept without it counts as approved. BrainForge sets every concept an ingestion creates or changes to `pending`, whatever the agent wrote.
- `brainforge approve <concept>` sets `approved` and adds `verified: {by: human:<git user>, at}`, which raises the concept to OKF's highest trust tier: a human has verified it.
- `brainforge discard <concept>` undoes a pending change by restoring the last approved version from git. A new concept becomes a tombstone (`approval: discarded`), so the agent doesn't create it again; search, reports and the Obsidian graph hide it.
- `audience` is one of the brain's audiences (see [brain-manifest.md](brain-manifest.md)). BrainForge keeps the value people set and gives new concepts the narrowest audience; the agent can't change it.
- `owner` names who is responsible, as the document says it. Approvals are routed by it.

## Links

Links are **relative** markdown links (`../decisions/go-live.md`). OKF allows both relative and `/`-absolute links. Relative links resolve correctly on GitHub's web view, in Obsidian and in editors, whereas `/`-absolute links break because the bundle sits under `knowledge/`.
